## Goal

Add the pure, host-tested **ring-out controller** to the CLI as
`cli/ringout_logic.{c,h}`. This is the only genuinely new logic in the feature: a
state machine that, given the latest RTA frame, decides the next action while
deliberately ramping a monitor toward (but never into) feedback. No sockets, no
time calls — same discipline as `toast_logic`.

See [`docs/ringout-design.md`](../docs/ringout-design.md) for the full design.

## Public contract

```c
typedef enum { RO_RAISE_GAIN, RO_PLACE_NOTCH, RO_BACK_OFF,
               RO_HOLD, RO_DONE, RO_ABORT } RingoutOp;

typedef struct {
    RingoutOp op;
    float gain_db;   /* for RO_RAISE_GAIN / RO_BACK_OFF: new driven gain */
    int   geq_par;   /* for RO_PLACE_NOTCH: 1..31 */
    float cut_db;    /* for RO_PLACE_NOTCH: notch depth (negative) */
} RingoutAction;

typedef struct {
    float start_gain_db, cur_gain_db, ceiling_db; /* gain ramp + hard ceiling */
    float step_db;                                /* per-RAISE increment */
    int   max_notches, n_notches;
    int   placed_par[31];                         /* bands already notched */
    float threshold_db, cut_db;                   /* detection + notch depth */
    int   confirm_frames, confirm_count, confirm_bin;
    float target_margin_db;                       /* stop once achieved */
    int   settle_frames, settle_count;            /* wait after a gain change */
    /* ...frame index supplied by caller; no internal time */
} RingoutState;

void          ringout_init(RingoutState *st, /* config args */);
RingoutAction ringout_step(RingoutState *st, const float *bins, const float *baseline);
```

## Acceptance Criteria

- [x] `cli/ringout_logic.h` + `.c` implement `ringout_init` and `ringout_step`,
      reusing `detect_peak` / `is_narrow_peak` from `toast_logic` for ring
      detection (do **not** re-implement detection).
- [x] State machine: after a gain change, wait `settle_frames`; analyse; if a
      confirmed narrow peak (`confirm_frames`) → `RO_PLACE_NOTCH` on its band +
      `RO_BACK_OFF`; else if stable → `RO_RAISE_GAIN` by `step_db`.
- [x] **Safety in the pure layer:** never emit `RO_RAISE_GAIN` that would exceed
      `ceiling_db` (emit `RO_DONE` instead); stop with `RO_DONE` when
      `target_margin_db` reached or `max_notches` placed; a band already in
      `placed_par` is never notched twice.
- [x] Reports final **gain-before-feedback margin** via state (ceiling vs highest
      stable gain achieved).
- [x] `cli/test_ringout_logic.c` (Unity-style, matching `test_toast_logic.c`):
      feed synthetic RTA frames with a rising narrowband peak and assert the
      action sequence — raise → settle → confirm → notch+backoff → … → done at
      ceiling. Cover: ceiling stop, max-notch stop, no-double-notch, abort path.
- [x] Wired into `cli/Makefile` `check` target (`test_ringout_logic`); all tests
      pass on the host.

## Progress

2026-06-29: Implemented `cli/ringout_logic.{h,c}` — pure `ringout_step()` state
machine (settle → analyze → confirm → notch+backoff / raise) over a
`RingoutConfig`/`RingoutState`, reusing `detect_peak`/`is_narrow_peak`. Safety

gain/notch actions; covers full two-ring sequence, ceiling/margin/max-notch

ceiling. Wired `test_ringout_logic` into the Makefile `check` target.

ringout 22), no `-Wall` warnings. Notch-failure→ABORT heuristic is intentionally
conservative; real-PA thresholds tuned in T-025 against the emulator.

## Notes

- Pure C, allocation-free, no `gettimeofday` — caller advances frames. This is
  what makes it portable to `ToastSaverCore` and ESP32 later.
- Detection thresholds mirror reactive defaults; tune in T-025 against the
  emulator, not here.
