## Goal

Move common OSC packet construction and parsing intent behind a deeper message
module so callers stop depending on byte offsets, padding rules, and endian
details.

## Acceptance Criteria

- [ ] A shared OSC message module exposes intent-level helpers for common
      packets used by X32Tap and XAir emulator behavior.
- [ ] Raw alignment, byte-order, and `/meters/6` packet layout details are
      internal to the OSC message module.
- [ ] Existing `ms_to_normalized`, `normalized_to_ms`, and `bpm_from_ms`
      behavior remains unchanged.
- [ ] Meter subscribe and meter response tests assert behavior through the new
      message interface rather than duplicating packet offsets in each caller.
- [ ] `make -C src check-build` passes for the affected targets.

## Notes

From architecture report: "Deepen OSC message construction" is strong because
callers currently know too much about padding, byte order, and magic offsets.

This is blocked by T-009 to avoid simultaneous churn in X32Tap while the mixer
UDP session interface is being introduced.
