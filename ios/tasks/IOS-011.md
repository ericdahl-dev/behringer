## Goal

Wire `RingoutSession` (IOS-010) into the SwiftUI layer so the operator can run a proactive ring-out pass from the app. Currently `RingoutSession` is implemented but not accessible from the UI — `ContentView` only exposes reactive mode (live feedback protection).

## Acceptance Criteria

- [ ] "Ring Out" button in the header or status bar starts/stops a ring-out session
- [ ] Ring-out config exposed in `ConfigView`: bus number, ceiling dB, step dB, target margin dB
- [ ] Phase display: calibrating / analyzing / settling / done / aborted with current gain and notch count
- [ ] Log panel shows `RingoutSession.logLines` during an active run
- [ ] `MixerConnection` (not `XR18Connection`) used for ring-out fader read/write
- [ ] Active ring-out notches shown in `SpectrumView` alongside reactive notches
- [ ] Stop button reverts notches and restores fader

## Notes

- `RingoutSession.init(connection: MixerConnection, audio: AudioCaptureEngine, fft: FFTEngine)`
- `ContentView` currently uses `XR18Connection` for reactive mode — need to add a `MixerConnection` alongside it, or unify both modes under `MixerConnection`
- `RingoutSession.Config` needs: `mixerModel`, `mixerHost`, `bus`, `fxSlot`, `rtaChannel`, `ringoutConfig`, `supervised`, `calibrationFrames`
