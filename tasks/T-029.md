## Goal

Extract a pure `toast_step()` function into `cli/toast_logic.{h,c}` that
mirrors the existing `ringout_step()` pattern: it takes RTA state and returns
an **action** — no OSC sends, no AppState, no global time. Today the reactive
detection orchestration lives inline in `run_detection()` inside
`XAir_ToastSaver.c` and is **entirely untested**: the confirm-accumulation
across 31 bands, the 3-frame confirmation window, the release ramp, and the
snap-back-to-full-cut on feedback return all live outside the test harness.
This closes the symmetry gap with `ringout_step()` and gives the reactive path
the same unit-test leverage the proactive path already has.

This is architecture candidate #2 from the 2026-06-29 review.

## Study first: `ringout_step()` is the model

Read `cli/ringout_logic.h` and `cli/ringout_logic.c` before designing anything.
`ringout_step(RingoutState*, bins, baseline) → RingoutAction` is the pattern to
follow exactly:
- Pure function: no I/O, no time, no global state.
- All mutable state in a typed struct (`RingoutState`).
- Caller dispatches on the returned action.
- Tested in `cli/test_ringout_logic.c` with synthetic RTA frames.

## What to build

### New types in `cli/toast_logic.h`

```c
typedef enum {
    TOAST_HOLD,          /* nothing to do this frame */
    TOAST_NOTCH,         /* apply a new notch cut on geq_par */
    TOAST_RELEASE_RAMP,  /* ramp an active notch toward flat; send ramp_val */
    TOAST_RELEASE_DONE   /* notch fully released; restore to flat (0.5) */
} ToastOp;

typedef struct {
    ToastOp op;
    int     geq_par;    /* 1–31; valid for TOAST_NOTCH, TOAST_RELEASE_RAMP,
                           TOAST_RELEASE_DONE */
    float   cut_val;    /* TEQ float applied on TOAST_NOTCH */
    float   ramp_val;   /* TEQ float to send on TOAST_RELEASE_RAMP */
} ToastAction;

typedef struct {
    /* per-band live state */
    int   active[31];
    float cut_val[31];
    int   release_hold[31];
    int   from_profile[31]; /* pinned — never auto-released */
    int   confirm_hold[31];
    /* config (set at init, read-only in step) */
    float threshold_dB;
    float cut_dB;
    int   release_frames;   /* release_sec * 20 (20 Hz RTA) */
    int   confirm_frames;
    float narrow_db;
    int   narrow_skip;
    int   narrow_span;
} ToastState;

void toast_state_init(ToastState *st,
                      float threshold_dB, float cut_dB,
                      float release_sec,  int   confirm_frames,
                      float narrow_db,    int   narrow_skip,
                      int   narrow_span);

/* Process one RTA frame.
 * Writes up to `cap` actions into `out`; returns the count written.
 * A single frame can produce up to 31 TOAST_RELEASE_RAMP/DONE actions
 * (one per ramping band) plus at most 1 TOAST_NOTCH.
 * Caller must size `out` accordingly (32 is safe). */
int toast_step(ToastState *st,
               const float *bins,     /* RTA_BIN_COUNT floats */
               const float *baseline, /* RTA_BIN_COUNT floats */
               ToastAction *out, int cap);
```

### `toast_step()` logic (port from `run_detection()`)

The function should do exactly what `run_detection()` does today, in the same
order — release pass then detection pass — producing actions instead of calling
`send_teq_band()` or mutating `AppState`:

**Release pass** (iterate all 31 bands):
- Skip inactive or `from_profile` bands.
- If `bins[TOAST_GEQ_BIN[j]] < baseline[TOAST_GEQ_BIN[j]] + threshold/2`:
  - Increment `release_hold[j]`.
  - Compute ramp: `t = release_hold[j] / release_frames` (clamp to 1).
  - Emit `TOAST_RELEASE_RAMP` with `ramp_val = cut_val[j] + (0.5 - cut_val[j]) * t`.
  - If `release_hold[j] >= release_frames`: emit `TOAST_RELEASE_DONE` instead;
    clear `active[j]`, reset `release_hold[j]`.
- Else (feedback returned mid-ramp):
  - If `release_hold[j] > 0`: snap back — emit `TOAST_RELEASE_RAMP` with
    `ramp_val = cut_val[j]` (the full cut); reset `release_hold[j] = 0`.

**Detection pass** (one peak per frame):
- Call `detect_peak(bins, baseline, threshold_dB, &peak_bin)` — existing function.
- If no peak: reset all `confirm_hold[]` to 0; return.
- Call `is_narrow_peak(bins, 100, peak_bin, narrow_skip, narrow_span, narrow_db)`.
- If not narrow: reset all `confirm_hold[]` to 0; return.
- Map `peak_bin` → `par` via existing `bin_to_geq_par(peak_bin)`.
- Accumulate: `confirm_hold[par-1]++`; reset all other `confirm_hold[]` to 0.
- If `active[par-1]`: return (already notched).
- If `confirm_hold[par-1] < confirm_frames`: return (not confirmed yet).
- Emit `TOAST_NOTCH` for `par`; update `active[par-1]`, `cut_val[par-1]`,
  reset `confirm_hold[par-1] = 0`.

**No calls to `send_teq_band`, `now_sec`, `printf`, or any global.**

### Migration in `XAir_ToastSaver.c`

1. Add `ToastState toast;` to `AppState` (alongside the existing `notches[]` and
   `confirm_hold[]` — migrate them into `ToastState` fields).
2. Initialize `toast_state_init(&s.toast, ...)` in `main()` with the CLI args.
3. Replace `run_detection(s)` with a call to `toast_step()`, then dispatch each
   returned `ToastAction`:
   - `TOAST_NOTCH`: `send_teq_band()`, update `s->toast.notched_at[par-1]`,
     log the notch. (Keep `notched_at` either in AppState or add it to
     ToastState — whichever is cleaner for the display code.)
   - `TOAST_RELEASE_RAMP`: `send_teq_band()` with `ramp_val`.
   - `TOAST_RELEASE_DONE`: `send_teq_band(0.5f)`, log the release.
4. `run_detection()` can be removed once the dispatch loop is wired.

Note: `notched_at` (the timestamp for the status-line display) is I/O state, not
detection state. Keep it in `AppState` or a parallel array — do not add
`gettimeofday()` to `ToastState`.

### Profile pre-loading (`from_profile`)

`ringout_load_profile()` currently sets `s->notches[j].from_profile = 1` directly.
After the migration it should instead set `s->toast.from_profile[j] = 1` and
`s->toast.active[j] = 1`. Update `ringout_load_profile()` accordingly.

### Makefile

`toast_logic.c` is already linked into `XAir_ToastSaver`. Add the new functions
there; no Makefile changes needed unless `toast_step` needs a new `.c` file.
Confirm `make XAir_ToastSaver` still compiles clean.

## Acceptance Criteria

- [ ] `toast_state_init()` and `toast_step()` are in `cli/toast_logic.h` and
      `cli/toast_logic.c`.
- [ ] `run_detection()` is removed from `XAir_ToastSaver.c`; replaced by a
      `toast_step()` dispatch loop.
- [ ] `AppState` no longer has `notches[31]` or `confirm_hold[31]` as direct
      members; they live in `ToastState`.
- [ ] `make XAir_ToastSaver` compiles clean, zero warnings.
- [ ] `make check` still passes.
- [ ] `cli/test_toast_logic.c` extended with `toast_step` integration tests:
      - Feed a flat baseline + a spike at a GEQ-aligned bin for 3 frames →
        assert `TOAST_NOTCH` on frame 3, `TOAST_HOLD` on frames 1–2.
      - After notching, feed the same bin below threshold for `release_frames`
        frames → assert `TOAST_RELEASE_RAMP` on each, then `TOAST_RELEASE_DONE`.
      - After release-done, feed the spike again → notch fires again (band is
        now inactive). Verifies the re-trigger path.
      - Mid-release: feed the spike back before `release_frames` → assert
        snap-back to `cut_val` (ramp_val == cut_val with release_hold == 0).
      - Narrowness gate: spike with a broadband neighbour shape → no notch
        (`confirm_hold` never increments).
      - `from_profile` band: mark band 5 as `from_profile`; feed its bin below
        threshold for `release_frames + 1` frames → assert no `TOAST_RELEASE_*`
        action (pinned bands are never released).
      - Confirm-counter reset: frame 1 peaks at par 10, frame 2 peaks at par 15
        → assert `confirm_hold[9] == 0` after frame 2 (different par resets).

## Notes

- This task is independent of T-028 (OscConn) — `toast_step()` is purely
  computational, no OSC involved. They can be done in either order. Recommended:
  T-028 first to clean up AppState, making the migration here less invasive.
- The existing `test_toast_logic.c` tests (`detect_peak`, `is_narrow_peak`,
  `db_to_geq_float`, etc.) must continue to pass unchanged.
- `ToastAction` uses `geq_par` (1-based, matching `bin_to_geq_par()` output)
  to stay consistent with `ringout_logic.h`'s `RingoutAction.geq_par`.
- Do **not** add timestamps, `printf`, or clock calls to `toast_step()`. The
  caller logs; the pure function only decides.
