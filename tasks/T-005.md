## Goal
Decide and implement the path for apps that are Windows-specific or depend on MFC, Win32, or MinGW-only assumptions.

## Acceptance Criteria
- [x] Every Windows-specific app from the inventory has a chosen strategy: native port, cross-compile, Wine/MinGW build, exclude with rationale, or separate Windows build.
- [x] Required Windows libraries such as `ws2_32`, `gdi32`, `comdlg32`, or MFC dependencies are identified per app.
- [x] Cross-compilable apps have documented build commands and output artifacts.
- [x] Apps that require MFC or unsupported GUI APIs have a written decision explaining the blocker.
- [x] Any source patches needed for portability are small, documented, and isolated.
- [x] The final status of each Windows-specific app is reflected back into the inventory.

## Notes
The upstream README says some programs are Windows applications and rely on Windows MFC libraries. This task prevents those apps from being silently counted as built native OS binaries when they are not.
