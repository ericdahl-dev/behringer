## Goal

Add `MixerModel.swift` to `ToastSaverCore` — a plain Swift struct that captures
everything that differs between an XR18 and an X32. No Apple framework imports.
Builds and tests on Linux with `swift test`.

Everything downstream that currently hardcodes XR18 values (port 10024, 6 buses,
4 FX slots) will accept a `MixerModel` instead. This task only defines the type and
its two static constants; wiring it into `MixerConnection` (IOS-009) is a separate
step.

## Reference

`cli/x32tap_logic.c` defines the C equivalent:

```c
const MixerProfile mixer_xair = {"xair", 10024, 4, 16};
const MixerProfile mixer_x32  = {"x32",  10023, 8, 32};
```

## Public interface

```swift
/// Describes the wire protocol differences between Behringer mixer families.
/// All fields are constant after construction — treat as a value type.
public struct MixerModel: Equatable, Sendable {
    /// Human-readable name, e.g. "XR18" or "X32".
    public let name: String

    /// UDP port the mixer listens on.
    public let port: UInt16

    /// OSC address the mixer pushes for RTA meter data (e.g. "/meters/4").
    public let metersPath: String

    /// Number of RTA bins in a meters packet (100 for XR18, 50 for X32).
    public let rtaBinCount: Int

    /// OSC address for the identity handshake query (e.g. "/xinfo" or "/info").
    public let handshakePath: String

    /// Number of input channels (18 for XR18, 32 for X32).
    public let inputChannels: Int

    /// Number of mix buses (6 for XR18, 16 for X32).
    public let busCount: Int

    /// Number of FX processor slots (4 for XR18, 8 for X32).
    public let fxSlots: Int

    public init(name: String, port: UInt16, metersPath: String, rtaBinCount: Int,
                handshakePath: String, inputChannels: Int, busCount: Int, fxSlots: Int)
}

public extension MixerModel {
    /// Behringer XR18 / XAir series (port 10024, /meters/4, 100 bins).
    static let xr18 = MixerModel(
        name:          "XR18",
        port:          10024,
        metersPath:    "/meters/4",
        rtaBinCount:   100,
        handshakePath: "/xinfo",
        inputChannels: 18,
        busCount:      6,
        fxSlots:       4
    )

    /// Behringer X32 / M32 series (port 10023, /meters/15, 50 bins).
    static let x32 = MixerModel(
        name:          "X32",
        port:          10023,
        metersPath:    "/meters/15",
        rtaBinCount:   50,
        handshakePath: "/info",
        inputChannels: 32,
        busCount:      16,
        fxSlots:       8
    )

    /// Returns the model matching a case-insensitive name string,
    /// or nil if unrecognised.
    static func named(_ name: String) -> MixerModel? {
        switch name.lowercased() {
        case "xr18", "xair": return .xr18
        case "x32", "m32":   return .x32
        default:             return nil
        }
    }
}
```

## Notes

- Do not add `check_outputs` or any function-pointer/closure analogue yet — that
  belongs in the doctor-mode task. Keep `MixerModel` a pure data struct.
- The `handshakePath` difference matters for `MixerConnection` (IOS-009): the XR18
  responds to `/xinfo` with a four-string reply; the X32 responds to `/info` with a
  simple echo. `MixerModel` just stores the path — the connection layer interprets it.
- The X32 `rtaBinCount` of 50 is only relevant if the app subscribes to the mixer's
  own RTA for correlation. For ring-out mode (phone mic as primary), this field is
  informational. Include it now so IOS-009 doesn't need to hard-code it.
