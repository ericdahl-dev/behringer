## Goal

Port `cli/ringout_logic.c` to Swift as `RingoutController` in `ToastSaverCore`.
Pure logic, no Apple framework imports, Linux-testable. This is the decision engine
for proactive ring-out: given per-GEQ-band levels (from the phone mic FFT) and a
slowmoving baseline, it decides whether to raise gain, back off, place a notch, or
stop. The iOS app layer (`RingoutSession`, IOS-010) owns all I/O; this class only
returns actions.

Read `cli/ringout_logic.h` and `cli/ringout_logic.c` before starting. Key constants

## Public interface

### RingoutConfig

```swift
/// Immutable configuration for one ring-out run. Set before calling init;
/// do not mutate during the run.
public struct RingoutConfig {
    /// Gain to start from (dB). Captured from the bus fader before the run.
    public var startGainDB: Float

    /// Hard upper bound — never command gain above this.
    public var ceilingDB: Float

    /// Gain increment per raise step and back-off amount (dB). Must be > 0.
    public var stepDB: Float

    /// Stop once this much headroom above startGainDB is achieved without feedback.
    public var targetMarginDB: Float

    /// Stop after placing this many notches regardless of margin.
    public var maxNotches: Int

    /// dB above baseline required to flag a potential feedback bin.
    public var thresholdDB: Float

    /// dB cut to apply when placing a notch (negative, e.g. -6).
    public var cutDB: Float

    /// Consecutive frames a peak must persist before a notch fires.
    public var confirmFrames: Int

    /// Frames to wait (at current gain) after a raise before analysing again.
    public var settleFrames: Int

    /// Consecutive quiet frames required before declaring the gain level stable.
    public var stableFrames: Int

    /// Narrowness gate: skip this many bins immediately adjacent to the peak.
    public var narrowSkip: Int

    /// Narrowness gate: sample this many bins beyond the skip zone on each side.
    public var narrowSpan: Int

    /// Narrowness gate: peak must exceed neighbour average by at least this many dB.
    public var narrowMinDB: Float

    public init(
        startGainDB: Float, ceilingDB: Float, stepDB: Float,
        targetMarginDB: Float, maxNotches: Int,
        thresholdDB: Float = 20.0, cutDB: Float = -6.0,
        confirmFrames: Int = 3, settleFrames: Int = 10, stableFrames: Int = 10,
        narrowSkip: Int = 2, narrowSpan: Int = 3, narrowMinDB: Float = 10.0
    )
}
```

### RingoutAction

```swift
/// One decision returned by RingoutController.step() per FFT frame.
public enum RingoutAction: Equatable {
    /// Stay at current gain; continue observing.
    case hold

    /// Command the bus fader to this gain (dB). Clamped to ceiling by the
    /// controller; caller must still send the OSC command.
    case raiseGain(to: Float)

    /// Feedback detected during a raise; back off to this gain (dB).
    case backOff(to: Float)

    /// Place a notch on this GEQ par (1–31) at cutDB from config.
    case placeNotch(par: Int, cutDB: Float)

    /// Run finished cleanly. margin is the achieved headroom in dB.
    case done(reason: RingoutDoneReason, margin: Float)

    /// Run terminated without achieving the margin.
    case abort(reason: RingoutDoneReason)
}

public enum RingoutDoneReason: Equatable {
    case targetMarginReached
    case ceilingReached
    case maxNotchesReached
}
```

### RingoutController

```swift
public final class RingoutController {
    public let config: RingoutConfig

    /// Current commanded gain in dB.
    public private(set) var currentGainDB: Float

    /// Number of notches placed so far.
    public private(set) var notchCount: Int

    public init(config: RingoutConfig)

    /// Process one FFT frame.
    ///
    /// - Parameter geqLevels: 31-element array of dBFS values, one per GEQ band.
    ///   `geqLevels[i]` corresponds to GEQ par `i+1`. Produced by sampling
    ///   `FFTEngine.process()` at `FFTEngine.geqBins[i]` for each band.
    /// - Parameter baseline: 31-element baseline (slow-moving average of geqLevels).
    ///   Caller is responsible for updating the baseline between frames using
    ///   `BaselineTracker`.
    /// - Returns: one `RingoutAction` for this frame.
    public func step(geqLevels: [Float], baseline: [Float]) -> RingoutAction

    /// Reset state to allow reuse (same config, fresh run). Resets gain to
    /// startGainDB, clears notch count, confirm/settle/stable counters.
    public func reset()
}
```

## step() algorithm

Port the `ringout_step()` function from `cli/ringout_logic.c` faithfully. Key states:

1. **Settling** — wait `settleFrames` frames after each gain raise before analysing.
   Return `.hold` every frame. Decrement counter.

2. **Analysing** — look for a narrow peak above threshold:
   - Use `FeedbackDetector.detectPeak(bins:baseline:threshold:)` on the 31-element
     `geqLevels` array (it works on any `[Float]`, the 31 vs 100 length doesn't matter).
   - If a peak is found, pass through `NarrownessFilter.isNarrowPeak` on `geqLevels`.
   - Accumulate `confirmFrames` consecutive narrow-peak frames on the same par.
   - On confirmation: return `.placeNotch(par:cutDB:)`. Increment `notchCount`.
     Check `maxNotches` stop condition — if reached, return `.abort(reason:.maxNotchesReached)`.
     Otherwise enter settling for the back-off.

3. **Back-off** — after placing a notch, back off by one `stepDB`:
   - Return `.backOff(to: currentGainDB - stepDB)`.
   - Re-enter settling, then stable-frames verification.

4. **Stable verification** — after settling, require `stableFrames` quiet frames
   (no peak above threshold) before declaring the current gain stable and raising.

5. **Raise** — once stable:
   - Next gain = `currentGainDB + stepDB`, clamped to `ceilingDB`.
   - If already at or above ceiling: check margin. If `currentGainDB - startGainDB
     >= targetMarginDB`, return `.done(reason:.targetMarginReached, margin:)`.
     Else return `.done(reason:.ceilingReached, margin:)`.
   - If `currentGainDB - startGainDB >= targetMarginDB`: also return
     `.done(reason:.targetMarginReached, margin:)` before raising.
   - Otherwise return `.raiseGain(to: nextGain)`.

**Important**: the controller never sends OSC. It only returns actions. The caller
(`RingoutSession`) applies the gain and notches via `MixerConnection`.

- [ ] `swift build` passes on Linux.
- [ ] `swift test` passes on Linux; tests cover:
  - Initial `step()` returns `.raiseGain` from `startGainDB + stepDB` after stable
    verification when no feedback is present.
  - Narrow peak on par 18 for `confirmFrames` consecutive calls returns
    `.placeNotch(par: 18, cutDB: config.cutDB)`.
  - After a notch, next action is `.backOff(to:)`.
  - `maxNotches` exceeded → `.abort(reason: .maxNotchesReached)`.
  - Gain reaching `ceilingDB` with insufficient margin → `.done(reason: .ceilingReached)`.
  - `targetMarginDB` achieved → `.done(reason: .targetMarginReached)`.
  - Settle counter prevents analysis for `settleFrames` frames after raise.
  - `reset()` returns controller to initial state.
- [ ] No `import Foundation`, no Apple frameworks.
- [ ] `currentGainDB` never exceeds `ceilingDB` after any sequence of `step()` calls.

## Notes

- `geqLevels` is 31 elements (one per GEQ par), not 100 (raw RTA bins). The
  `FeedbackDetector.detectPeak` and `NarrownessFilter.isNarrowPeak` functions work
  on any `[Float]`; the narrowness skip/span values are in GEQ-par units here, not
  RTA-bin units. The CLI uses skip=2, span=3 on 100 bins; on 31 pars the same values
  produce a wider gate — that is intentional and acceptable for ring-out.
- The controller works with GEQ par indices (1–31), not RTA bin indices. The caller
  (IOS-010 `RingoutSession`) is responsible for mapping FFT output to `geqLevels`
  using `FFTEngine.geqBins`.
- Do not add supervised-mode (pause-for-confirmation) logic here. That belongs in
  `RingoutSession` (IOS-010) which can pause before applying a `.raiseGain` action.
