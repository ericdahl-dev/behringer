## Goal

Add X32/M32 support behind a `--model x32` flag. The X32 family shares the
same OSC wire format and all control algorithms with the XR18, but differs in:
port number, RTA meter path, channel/bus/FX limits, and doctor-mode preflight
(X32 uses FX rack GEQ/TEQ, not bus insert GEQ/TEQ).

Everything else — the 100-bin frequency table, `TOAST_GEQ_BIN`, the
`/-prefs/rta/*` config paths, `/fx/[N]/par/[01...64]` notch writes, blob
encoding (short/256.0 = dBFS), and all ring-out / toast logic — is identical.

## Source of truth

Unofficial X32/M32 OSC Remote Protocol v4.02 (Jan 2020) — Patrick-Gilles
Maillot. Stored at `docs/url.txt` (https://tostibroeders.nl/wp-content/uploads/2020/02/X32-OSC.pdf).

Key findings from doc:
- `/meters/4` on X32 = 82 floats of in/out metering — **not the RTA**
- `/meters/15` on X32 = 100 × 16-bit shorts = RTA (same encoding, same 100-bin
  frequency table 20 Hz–18.66 kHz, bin 56 ≈ 947 Hz)
- `/-prefs/rta/*` paths identical to XR18
- FX par structure identical: GEQ pars 1–31 = 31 bands, par 32 = master

## Architecture difference: doctor mode

**XR18**: GEQ/TEQ is inserted directly on a bus (bus insert slot). Doctor
checks that bus N's insert effect is a GEQ or TEQ type. Fix sets the insert
type.

**X32**: Buses have a 4-band PEQ built-in; there is no GEQ/TEQ bus insert
slot. The standard X32 practice is to load GEQ/TEQ into an FX rack slot
(1–8) and route the bus output through it. Doctor mode for `--model x32`
therefore checks the FX rack slot, not a bus insert.

## CLI flag

```
--model {xr18,x32}   Mixer model (default: xr18)
```

All existing behaviour is unchanged when `--model xr18` (or flag omitted).

## Changes

### Port
| Model | Port  |
|-------|-------|
| xr18  | 10024 |
| x32   | 10023 |

### RTA meter subscription (`osc_io.c`)
Parameterise `osc_subscribe_meters4()` to accept the meter path:

```c
void osc_subscribe_meters(OscConn *c, const char *meter_path);
/* xr18: meter_path = "/meters/4"  */
/* x32:  meter_path = "/meters/15" */
```

Keep `osc_subscribe_meters4()` as a thin wrapper calling
`osc_subscribe_meters(c, "/meters/4")` so existing call sites compile without
change.

### Blob parsing (`toast_logic.c`)
`parse_meters4_blob()` currently validates `n_vals == 100`. The X32 doc
describes `/meters/15` as "50 × 32-bit values" — the `int2` field in the blob
header may be 50 (50 four-byte chunks each holding 2 shorts) rather than 100.
This is the **only thing requiring real X32 hardware to verify**.

Add a fallback branch:

```c
if (n_vals == 100) {
    /* existing XR18 path: 100 × int16 LE at blob+8 */
} else if (n_vals == 50) {
    /* X32 path: 50 × uint32 LE, each holds 2 × int16 LE */
    for (int i = 0; i < 50; i++) {
        int16_t lo, hi;
        memcpy(&lo, blob + 8 + i*4,     2);
        memcpy(&hi, blob + 8 + i*4 + 2, 2);
        bins[i*2]   = (float)lo / 256.0f;
        bins[i*2+1] = (float)hi / 256.0f;
    }
} else {
    return -1;
}
```

If hardware testing shows `n_vals == 100` on X32 too, delete the `n_vals==50`
branch and add a comment explaining the doc's "50 × 32-bit" phrasing.

### Doctor mode — X32 variant

For `--model x32`, `run_doctor()` replaces the bus-insert check with an
FX-slot check:

| XR18 doctor check | X32 doctor check |
|---|---|
| Bus N insert type is GEQ or TEQ | FX slot S type is GEQ, GEQ2, TEQ, or TEQ2 |
| Fix: set bus insert type | Fix: set `/fx/[S]/type` to GEQ (enum value 17 for slots 1–4, enum value 0 for slots 5–8) |

OSC to read FX type: `GET /fx/[S]/type` → int.

Type enum values for GEQ (slots 1–4): `GEQ=17`, `TEQ=19`, `GEQ2=16`,
`TEQ2=18` (0-based index in the FX type enum list from the doc).

Type enum values for GEQ (slots 5–8): `GEQ=1`, `TEQ=3`, `GEQ2=0`, `TEQ2=2`.

Doctor output line replaces "Bus N: TEQ" with "FX slot S: GEQ" for X32.

There is **no check of bus→FX routing** — that is a one-time user setup on
the X32, not something we automate.

### RTA source mapping (`/-prefs/rta/source`)
X32 source index range extends to 73 (Main=72, Mono=73 vs XR18's narrower
range). No code change needed; we pass the integer directly. Document the
wider range in help text when `--model x32`.

### Limits

| Parameter     | XR18 max | X32 max |
|---------------|----------|---------|
| `-c` channel  | 18       | 32      |
| `--ringout-bus`| 6       | 16      |
| `-s` FX slot  | 4        | 8       |

Validation in `main()` reads from a model struct rather than hard-coded
constants.

## Signal generator (X32 only)

The X32 has a built-in oscillator accessible via OSC. This enables automated
bin calibration without external hardware.

### OSC paths

| Path | Type | Range | Notes |
|------|------|-------|-------|
| `/-stat/osc/on` | enum | 0=OFF, 1=ON | master enable |
| `/config/osc/type` | enum | 0=SINE, 1=PINK, 2=WHITE | generator type |
| `/config/osc/f1` | logf | [20.0, 20000.0] Hz | frequency 1 |
| `/config/osc/f2` | logf | [20.0, 20000.0] Hz | frequency 2 |
| `/config/osc/fsel` | enum | 0=F1, 1=F2 | active frequency select |
| `/config/osc/level` | level | [-90.0, +10.0] dB | output level |
| `/config/osc/dest` | int | 0–25 | destination: 0=MixBus1…15=MixBus16, 16=L, 17=R, 18=L+R, 19=M/C, 20–25=Matrix1–6 |

### Calibration procedure

1. `/-stat/osc/on ,i 1` — enable oscillator
2. `/config/osc/type ,i 0` — SINE
3. `/config/osc/dest ,i <N>` — route to a MixBus N-1 (0-indexed)
4. `/-prefs/rta/source ,i <M>` — point RTA at that bus (Bus01=48, Bus02=49, …)
5. Sweep `/config/osc/f1` through known frequencies; for each, read `/meters/15`
   and record the bin index of the peak — builds an empirical bin→Hz map
6. `/-stat/osc/on ,i 0` — disable

This confirms the 100-bin frequency table without a pistonphone and can
validate the `n_vals=50` parsing path on first connection.

Future task: add `--calibrate` flag that runs this sweep automatically on X32,
writes the empirical map to a JSON file, and uses it instead of the hardcoded
`TOAST_GEQ_BIN` table if the map exists.

## Resolved: `n_vals` format

**Confirmed from doc (page 19 of X32-OSC.pdf)**: `/meters/15` returns "50 ×
32-bit values as a single OSC blob. The 32-bit values returned are representing
100 successive little endian coded short ints." The blob header therefore sends
`n_vals = 50`. The `n_vals=100` path in `parse_meters4_blob` remains as the
XR18 path; the X32 takes the `n_vals=50` branch.

## Notes

- FX slots 5–8 on X32 have a narrower effect type enum (33 types vs 60 for
  slots 1–4) but GEQ/TEQ appear in both, so doctor fix works for all 8 slots.
- The subscription wire format already uses `siii` (string + 3 ints); changing
  the string from `/meters/4` to `/meters/15` is the only send-side change.
- `/xinfo` response identifies the model ("X32" vs "XR18") — consider auto-
  detecting model from `/xinfo` and only requiring `--model` as an override.
