## Goal

Replace the current raw-ANSI display in `XAir_ToastSaver.c` with a proper
ncurses TUI that covers every app mode — doctor, reactive, and ring-out — as a
unified interface. The user should never need to look at scrolling terminal
text; everything the app knows is visible in structured panels with live
updates.

T-028 (OscConn) and T-029 (toast_step) may be in flight concurrently. This
task touches only the display and input layer; logic and OSC send calls are
unchanged.

## Design

### Shared chrome (all modes)

```
┌─ XAir Toast Saver ── 192.168.2.146 ── ch:1 ── bus:1 ── thr:20dB ───────────┐
│                       [mode-specific panel]                                   │
├─ Status ─────────────────────────────────────────────────────────────────────┤
│  [state text]                          q quit   Enter confirm   ? help        │
└──────────────────────────────────────────────────────────────────────────────┘
```

Top bar: fixed single row — IP, channel, active bus, threshold. Never scrolls.
Bottom bar: fixed two rows — state line left, key hints right.

### Spectrum panel (reactive + ring-out)

- Width: `COLS - 2` (fills terminal width, not hard-coded 100)
- Bins scaled to panel width via nearest-bin mapping
- 5-level gradient per bin based on `bins[i] - baseline[i]`:
  - `  ` < 5 dB above baseline
  - `░` 5–10 dB
  - `▒` 10–15 dB
  - `▓` 15–threshold dB
  - `█` (yellow) ≥ threshold
  - `N` (red) — active notch at this bin position
- Second row: `▼` (red) under each active notch bin
- Frequency ruler row: `20Hz` left, `1kHz` at bin 56 proportionally, `20kHz` right
- During calibration: replace spectrum with a progress bar:
  `Calibrating... [████████████░░░░░░░░]  32/40 frames`

### Mode: Doctor

```
┌─ XAir Toast Saver ── 192.168.2.146 ────────────────── doctor ───────────────┐
│                                                                               │
│  [PASS] XR18 reachable                                                        │
│  [PASS] Bus 1: TEQ                                                            │
│  [FAIL] Bus 2: PEQ  ← needs GEQ or TEQ          f fix this                   │
│  [PASS] Bus 3: GEQ                                                            │
│  [FAIL] Bus 4: PEQ  ← needs GEQ or TEQ          f fix this                   │
│  [PASS] Bus 5: TEQ                                                            │
│  [PASS] Bus 6: GEQ                                                            │
│  [PASS] LR: TEQ                                                               │
│  [PASS] RTA streaming: peak -51.2 dBFS                                        │
│                                                                               │
│  2 issues found.                                                               │
│                                                                               │
├─ Status ─────────────────────────────────────────────────────────────────────┤
│  doctor complete                                   f fix-all   q quit         │
└──────────────────────────────────────────────────────────────────────────────┘
```

Key `f` triggers `--fix` in-TUI (re-runs `run_doctor` with fix=1, redraws
results). Doctor results stream in as each check completes — don't wait for all
to finish before drawing.

### Mode: Reactive

```
┌─ XAir Toast Saver ── 192.168.2.146 ── ch:1 ── thr:20dB ── reactive ────────┐
│ 20Hz                          1kHz                              20kHz         │
│ ░▒░ █▓▒░   ▒█▓░  N    ▒░     ▓█▒░      N   ░▒█▓░                           │
│               ▼                          ▼                                    │
├─ Active Notches ─────────────────────────────────────────────────────────────┤
│  1kHz    -6dB   pinned  [profile]                                             │
│  500Hz   -6dB   12.4s   [████████████░░░░░░░░]  releasing                    │
├─ Log ────────────────────────────────────────────────────────────────────────┤
│  12:04:31  notch    1kHz    bin 56   -51.2 dBFS                               │
│  12:04:19  notch    500Hz   bin 43   -48.7 dBFS                               │
│  12:03:55  release  250Hz   9.8s                                              │
├─ Status ─────────────────────────────────────────────────────────────────────┤
│  listening · 2 notches · noise floor -72.4 dBFS        q quit                │
└──────────────────────────────────────────────────────────────────────────────┘
```

Active notches panel:
- `pinned [profile]` for `from_profile` notches (never show release bar)
- Release progress bar: `█` per frame elapsed / release_frames, `░` remaining
- Disappears when notch releases

Log panel:
- Scrollable (↑/↓ keys); auto-scrolls to bottom on new entries unless user
  has scrolled up
- Timestamps from `now_sec()`
- Kept in a ring buffer (last 200 entries)

### Mode: Ring-out

```
┌─ XAir Toast Saver ── 192.168.2.146 ── ch:1 ── bus:1 ── ring-out ───────────┐
│ 20Hz                          1kHz                              20kHz         │
│ ░▒░   ▒█▓░  N       ░▒█▓░         ▓█▒░      ░▒█▓░                           │
│               ▼                                                                │
├─ Gain Ladder ────────────────────────────────────────────────────────────────┤
│   0dB ┤ ceiling                                                                │
│  -2dB ┤                                                                        │
│  -4dB ┤ ◄── now  SETTLING (6/10)                                               │
│  -6dB ┤──● 1kHz                                                                │
│  -8dB ┤──● 500Hz                                                               │
│ -12dB ┤ start (fader: 0.712)                                                   │
├─ Log ────────────────────────────────────────────────────────────────────────┤
│  +04s  raise     → -10dB                                                      │
│  +08s  notch     500Hz   -6dB at -8dB                                         │
│  +09s  back-off  → -9dB                                                       │
│  +14s  raise     → -8dB                                                       │
│  +18s  notch     1kHz    -6dB at -6dB                                         │
├─ Status ─────────────────────────────────────────────────────────────────────┤
│  SETTLING · 2 notches · margin 2.0/6.0dB              q abort                 │
└──────────────────────────────────────────────────────────────────────────────┘
```

Gain ladder panel:
- Rows from `ceiling` (top) to `start` (bottom); current gain marked with `◄──`
- Notch discoveries marked as `──● {freq}` at the gain where they appeared
- `SETTLING`, `ANALYZING`, `RAISING`, `BACKING OFF`, `DONE`, `ABORTED` states
- Ladder height adapts to panel height; if range > available rows, scale ticks

Supervised mode: status bar becomes:
```
│  WAITING — press Enter to raise to -3dB              Enter confirm   q abort  │
```
`Enter` unblocks the raise; TUI stays live (spectrum still updates) while waiting.

Ring-out completion — ladder stays visible with all notch markers, status shows:
```
│  DONE · margin 7.2dB · 3 notches · profile saved: toast-ch1.json    q quit   │
```
or on abort:
```
│  ABORTED · fader restored · notches reverted                          q quit  │
```

## Implementation notes

### ncurses setup

```c
#include <ncurses.h>

void tui_init(void) {
    initscr();
    start_color();
    use_default_colors();
    cbreak(); noecho();
    keypad(stdscr, TRUE);
    nodelay(stdscr, TRUE);   /* non-blocking getch() */
    curs_set(0);             /* hide cursor */
}
```

Color pairs (define in `tui_init`):
- `CP_DIM` — low spectrum bins
- `CP_MID` — moderate excess
- `CP_HIGH` — near-threshold
- `CP_PEAK` — at/above threshold (yellow on default)
- `CP_NOTCH` — notched bin (red on default)
- `CP_PASS` — doctor PASS (green)
- `CP_FAIL` — doctor FAIL (red)
- `CP_LADDER_NOW` — current gain row (cyan)
- `CP_LADDER_NOTCH` — notch discovery row (yellow)

### Non-blocking input loop

Replace `getchar()` (supervised ring-out) with a check inside the RTA frame
loop:

```c
int ch = getch();   /* nodelay — returns ERR immediately if no key */
if (ch == 'q' || ch == KEY_F(1)) g_running = 0;
if (ch == '\n' || ch == KEY_ENTER) ro_confirmed = 1;
if (ch == KEY_UP)   log_scroll--;
if (ch == KEY_DOWN) log_scroll++;
```

### SIGWINCH (resize)

```c
static volatile int g_resized = 0;
static void sigwinch_handler(int s) { (void)s; g_resized = 1; }
/* in main loop: */
if (g_resized) { endwin(); refresh(); clear(); tui_redraw_all(&s); g_resized = 0; }
```

### Extraction: `tui.{h,c}`

Extract all ncurses code into `cli/tui.h` and `cli/tui.c`. `XAir_ToastSaver.c`
calls only:

```c
void tui_init(void);
void tui_shutdown(void);
void tui_draw_doctor(const DoctorResult *results, int n);
void tui_draw_reactive(const AppState *s, const char **log, int log_n, int scroll);
void tui_draw_ringout(const AppState *s, const RingoutState *rs,
                      const char **log, int log_n);
void tui_handle_key(int ch, int *running, int *ro_confirmed, int *log_scroll);
```

This keeps ncurses out of `XAir_ToastSaver.c` and makes the display layer
replaceable.

### Remove / deprecate

- All raw `printf("\033[...H...")` cursor positioning in `XAir_ToastSaver.c`
- `print_static_display()` and `draw_display()` — replaced by `tui_draw_reactive()`
- The `--verbose` / `-v` flag: replace with a log panel that always shows
  events. Verbose mode can mean "show raw RTA numbers in the log" rather than
  disabling the TUI entirely. Update help text accordingly.

## Notes

- Link with `-lncurses` (or `-lcurses` on systems without ncurses). Add to
  `cli/Makefile` `XAir_ToastSaver` link line only — test binaries don't need it.
- `nodelay(stdscr, TRUE)` means `getch()` returns `ERR` immediately when no key
  is pressed — the RTA frame loop drives the redraw cadence (~20 Hz), not a
  separate ncurses event loop.
- The log ring buffer (200 entries) lives in `XAir_ToastSaver.c` or a small
  `log_buf.{h,c}`; `tui_draw_reactive` and `tui_draw_ringout` receive it as a
  pointer + count.
- If T-028 (OscConn) and T-029 (toast_step) land first, the `AppState` fields
  the TUI reads may have moved into `ToastState` / `OscConn`. Coordinate or
  adapt — the TUI interface above uses `AppState *s` as a convenience; adjust
  the actual signature to whatever structs exist at implementation time.
- notcurses is explicitly out of scope — it's not on every system and adds a
  less common dependency for marginal visual gain.
