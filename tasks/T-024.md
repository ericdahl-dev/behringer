## Goal

Make the proactive→reactive handoff real: **save** the ring-out result to a file
and **load** it at the start of reactive mode so the static notches are
pre-placed and live protection only defends the remaining margin.

See [`docs/ringout-design.md`](../docs/ringout-design.md) ("One pipeline").

## Acceptance Criteria

- [x] `--save-profile PATH` (ring-out mode): writes the result — per-band notch
      depths (31 bands), gain-before-feedback margin, target bus + FX slot, mixer
      model, and an ISO timestamp — as a human-readable text file. Format
      documented in `ringout_profile.c`.
- [x] `--load-profile PATH` (reactive mode): parses the file, applies the saved
      notches via `send_teq_band`, then runs normal reactive detection on top.
- [x] Loaded static notches carry a `from_profile` flag; **v1 behaviour: they are
      pinned** (the release pass skips them) so the soundcheck notches stay put
      while live-detected notches still auto-release.
- [x] Round-trip test: serialize → parse → re-serialize is byte-identical
      (`test_ringout_profile.c`, host fixture, no mixer).
- [x] Mismatch guard: refuses to load a profile whose **model or FX-slot** disagree
      with the current args. (Bus is informational in reactive mode, which has no
      bus argument — see Notes.)
- [x] `--help` documents both flags.

## Notes

- This is also the seam for the bigger picture: a ring-out profile is exactly the
  kind of artifact the future "console recall in an Ableton session" idea would
  bind per-song. Keep the format self-contained and portable.
- No new control logic — serialization + apply-on-startup only.

## Progress

2026-06-29: Added `cli/ringout_profile.{c,h}` — a pure, host-tested text
serialize/parse for the ring-out result (model, bus, fx_slot, margin, ISO
timestamp, 31 band depths) + `cli/test_ringout_profile.c` (18 asserts:
round-trip byte-identical, hand-written parse, missing-field rejection,
buffer-too-small). Wired into `make check`. In `XAir_ToastSaver.c`:
`ringout_save_profile` (ring-out completion → file), `ringout_load_profile`
(reactive startup → parse + guard + pre-place pinned notches), a `from_profile`
flag on `NotchState` that the release pass skips, and `--save-profile` /
`--load-profile` args. `make all` clean; `make check` 45/16/22/18 green.

Deviations: (1) v1 loads profile notches **pinned** (never auto-released) rather
than governed by the release timer — the more useful default for static
soundcheck notches. (2) The mismatch guard checks **model + fx_slot**, not bus,
because reactive mode has no bus concept (the profile records the bus it was made
for as provenance, printed on load). Live mixer/emulator validation is T-025.
