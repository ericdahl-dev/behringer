## Goal

Introduce a deeper mixer UDP session module by moving X32Tap's socket lifecycle,
handshake, keepalive, polling, send, receive, and close behavior behind one
small interface.

## Acceptance Criteria

- [ ] X32Tap uses a shared mixer UDP session module instead of local `udp_send`,
      `udp_poll`, `udp_recv`, and socket setup helpers.
- [ ] The session interface owns `/info` handshake behavior for X32 and XAir
      ports without exposing caller-managed socket globals.
- [ ] `/xremote` keepalive behavior remains intact for X32Tap auto mode.
- [ ] Existing X32Tap manual tap, auto tap, FX slot selection, and XAir/X32 mode
      behavior still build and smoke-test successfully.
- [ ] A focused test or smoke check verifies at least one successful session
      handshake path through the new interface.

## Notes

From architecture report: "Deepen the mixer UDP session" was the top
recommendation. The current friction is that UDP lifecycle knowledge leaks
across app modules while `X32Connect` exposes globals as its interface.

Keep this slice narrow: prove the deeper module through X32Tap first. Broader
migration of other apps can follow after the interface survives one real caller.
