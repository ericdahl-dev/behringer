## Goal

Produce a confirmed `RTA_BIN_FREQ[100]` table mapping each `/meters/4` RTA bin to
its center frequency (Hz). This is **shared infrastructure**: the mic-cal
correction (T-026) and the pink-noise response-EQ / tune mode
(`docs/system-tune-design.md`, T-021+) both need it to relate bins to a
frequency-indexed curve. Today the bin→Hz mapping is assumed, never measured.

## What we already know (anchors, do not re-derive blindly)

- The CLI uses **`/meters/4` = 100 bins** (`cli/XAir_ToastSaver.c:subscribe_meters4`,
  `parse_meters4_blob`). Treat 100-bin /meters/4 as the RTA unless the sweep
  disproves it.
- **Known anchor:** `cli/toast_logic.c` `TOAST_GEQ_BIN` is calibrated so that
  **1 kHz → bin 56** (pistonphone 1 kHz @ 94 dB). The 31 GEQ bins
  (`0,3,7,…,56,…,99`) span the 100 RTA bins roughly logarithmically — strong hint
  the layout is a fixed ~1/6-octave-ish log map from ~20 Hz (bin 0) to ~20 kHz
  (bin 99). The sweep confirms/refutes this and fills the exact centers.
- **Open ambiguity:** earlier meter research floated `/meters/5` (44 values) as an
  RTA candidate. Resolve it here: confirm `/meters/4` (100) is the RTA we use and
  note what `/meters/5` actually is, so the question is closed for good.

## Method (empirical tone sweep)

1. Drive a **known single tone** into the RTA source channel — use the console's
   internal generator (sine) routed to that input, or an external generator.
2. Read `/meters/4`, record **which bin peaks** for each tone.
3. Sweep a log set of frequencies across 20 Hz–20 kHz (e.g. 1/6-oct steps, plus
   the ISO centers 31.5/63/125/250/500/1k/2k/4k/8k/16k for cross-checks).
4. Interpolate bin centers between measured anchors; verify monotonic and that
   1 kHz lands on bin 56.

A small capture harness is fine (reuse the existing OSC subscribe/parse path; a
`--rta-probe` mode in `XAir_ToastSaver` that prints peak bin for the current
input is a cheap way to collect data live).

## Deliverable: `cli/rta_bins.{c,h}`

```c
/* Center frequency (Hz) of each /meters/4 RTA bin, empirically calibrated. */
extern const float RTA_BIN_FREQ[100];

/* Nearest RTA bin for a frequency (inverse of the table). */
int rta_bin_for_freq(float hz);
```

Host-testable: spot-check `RTA_BIN_FREQ[56] ≈ 1000`, monotonic increasing, and
`rta_bin_for_freq(1000) == 56`.

## Acceptance Criteria

- [ ] `cli/rta_bins.c` + `cli/rta_bins.h` with the measured `RTA_BIN_FREQ[100]`.
- [ ] 1 kHz maps to bin 56 (consistent with the GEQ calibration anchor).
- [ ] Table is monotonic increasing across the band; endpoints documented.
- [ ] `/meters/5` clarified in a comment / `docs/` note (what it is vs /meters/4).
- [ ] `cli/test_rta_bins.c` in the Makefile; `make test_rta_bins` passes
      (anchor + monotonicity + `rta_bin_for_freq` round-trip).
- [ ] Method + raw sweep data captured in `docs/` so the table is reproducible.
