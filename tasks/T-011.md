## Goal

Concentrate build target facts in one catalog so the Makefile, build checks,
and inventory documentation stop drifting independently.

## Acceptance Criteria

- [ ] Build target names, source files, required libraries, class, smoke command,
      and expected smoke output are represented in one maintained catalog.
- [ ] `test_build.py` reads target and smoke-check data from the catalog instead
      of duplicating its own target list.
- [ ] The Makefile or documented build workflow can consume the same target
      facts, or the task records why that is not practical yet.
- [ ] `APP_INVENTORY.md` and `BUILDING.md` are updated to describe the catalog
      as the source of truth for build target metadata.
- [ ] `make -C src check-build` and `make -C src check-toolchain` pass.

## Notes

From architecture report: "Deepen the build target catalog" is worth exploring.
The current friction is that target facts are repeated across `Makefile`,
`test_build.py`, `APP_INVENTORY.md`, and `BUILDING.md`.
