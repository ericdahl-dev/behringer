## Goal

Replace the single-frequency linear feedback model in `test_ringout_emu.py`
with a multi-mode `RoomModel` that supports named presets and JSON room files.
The existing assertion scenarios stay unchanged and CI-safe. Richer rooms are
opt-in via `--room` / `--room-file`.

## Room model

Each room is a list of **modes**:

```json
[
  {"bin": 56, "onset_db": -6.0, "slope": 10.0, "decay_frames": 1},
  {"bin": 23, "onset_db": -4.0, "slope":  8.0, "decay_frames": 3}
]
```

| Field          | Meaning                                                         |
|----------------|-----------------------------------------------------------------|
| `bin`          | RTA bin [0–99] where this mode rings                            |
| `onset_db`     | gain_db above which feedback starts                             |
| `slope`        | dBFS added per dB of gain above onset                           |
| `decay_frames` | frames for level to ramp up/down after gain changes (≥1)        |

`model_bins(gain_db, notched_pars)` returns `float[100]`:
- For each mode: `ring = max(0, (gain_db - onset_db) * slope)`
- If `mode.bin`'s GEQ par is in `notched_pars`: `ring = 0` (notch kills it fully)
- Apply `decay_frames` smoothing: each frame, level moves 1/decay_frames toward
  the target (so `decay_frames=1` = instant, current behavior)
- `bins[mode.bin] = -90.0 + ring`; all other bins stay at -90.0

No notch energy redistribution (deferred — add when a real room triggers it).

## Named presets

| Name       | Description                                    | Modes |
|------------|------------------------------------------------|-------|
| `flat`     | Current behavior — single 1 kHz mode, instant | 1     |
| `bathroom` | 3 strong high-freq modes, fast onset           | 3     |
| `lecture`  | 5 modes spread 200 Hz–8 kHz, slower onset      | 5     |
| `gymnasium`| 8 modes, high slope, long decay                | 8     |
| `custom`   | Load from `--room-file <path.json>`            | —     |

`flat` must be byte-for-byte equivalent to the current model so existing
assertion scenarios are unaffected.

## CLI flags

```
--room <name>        Use named preset (default: flat)
--room-file <path>   Load JSON room file (implies --room custom)
--debug-bins         Print active bin levels each RTA frame to stderr
```

`--debug-bins` format (one line per frame, stderr only):
```
[emu] frame 42  bin56=-12.3  bin23=-90.0  gain=-4.0dB
```
Only prints bins that belong to active modes, not all 100.

## File layout

All changes in `cli/test_ringout_emu.py`:

- `class RoomModel`: `__init__(modes)`, `bins(gain_db, notched_pars) -> list[float]`
- `PRESETS: dict[str, list[dict]]` — the four named presets as inline data
- `load_room(args) -> RoomModel` — resolves `--room` / `--room-file`
- `run(ceiling, abort_after_s, room, debug_bins)` — passes `RoomModel` through
- `main()` — adds `argparse` for `--room`, `--room-file`, `--debug-bins`; existing
  two scenarios still run when no `--room` is given (or `--room flat`)

No new files. No Makefile changes. No new test binary.

## Assertion scenarios

Unchanged. Both scenarios use `flat` (1 mode, decay=1 = current behavior).
The harness must still pass `make check`-equivalent when invoked as:

```
python3 cli/test_ringout_emu.py build/XAir_ToastSaver
```

## Acceptance criteria

- [ ] `python3 test_ringout_emu.py build/XAir_ToastSaver` — both scenarios pass
      (no regression)
- [ ] `python3 test_ringout_emu.py build/XAir_ToastSaver --room gymnasium` —
      runs without error; controller converges or hits max-notches
- [ ] `python3 test_ringout_emu.py build/XAir_ToastSaver --room-file r.json` —
      loads custom JSON, runs scenario 1 against it
- [ ] `--debug-bins` prints per-frame mode levels to stderr
- [ ] `flat` preset produces identical bin values to the original `model_bins()`

## Notes

- Keep `decay_frames` clamped to ≥1 so `flat` stays instant and deterministic.
- The emulator is never imported by test binaries — no need for a module
  interface, argparse at top level is fine.
- Redistribution (energy shift to adjacent bins on notch) deferred to a future
  task once a real room triggers the failure mode.
