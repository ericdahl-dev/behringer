## Goal

Validate the full ring-out loop end-to-end against the on-device **X32 emulator**
(`esp32/X32_emulator/`) and prove the safety properties hold, without risking a
real PA. Tune the detection/ramp defaults here.

See [`docs/ringout-design.md`](../docs/ringout-design.md) ("Safety").

## Acceptance Criteria

- [ ] A repeatable test rig drives `--ringout` against the emulator with a
      **synthetic feedback source**: either inject crafted `/meters/4` frames
      (a narrowband peak whose level tracks the commanded bus gain), or a small
      script that raises a bin as gain rises. Document the rig in the task.
- [ ] **Closed-loop behaviour confirmed:** as driven gain rises the synthetic
      peak grows; the app notches the correct band; after the notch the peak
      stops growing; the ramp resumes. Capture a run log.
- [ ] **Safety asserted (the point of this task):**
  - driven bus gain **never exceeds** `--ringout-ceiling`;
  - Ctrl-C / `RO_ABORT` snaps the bus fader back to its recorded start value
    (verify via emulator state read-back);
  - run terminates on ceiling, target margin, and max-notches as configured.
- [ ] Reported gain-before-feedback margin matches the synthetic setup within a
      defined tolerance; notched bands match the injected frequencies.
- [ ] Handoff verified: `--save-profile` then reactive `--load-profile` starts
      with the notches pre-placed (observe initial TEQ state on the emulator).
- [ ] Findings (good defaults for threshold / step / settle / confirm) written
      back into `docs/ringout-design.md` and the `--help`/defaults.

## Notes

- The emulator manages OSC state only (no audio), so the "feedback" is modelled
  in the test harness, not acoustically — sufficient to validate control logic,
  ramp, ceiling, abort, and profile handoff.
- Real-PA acoustic validation is a separate, supervised field test — out of scope
  here and explicitly noted so nobody assumes the emulator pass means PA-safe.
