## Goal

Replace the `if (s->model == &MODEL_XR18)` pointer comparison inside
`run_doctor()` with a function pointer on `MixerModel`, eliminating the
hardcoded model branch and making `run_doctor()` fully model-agnostic.

## Context

After T-033, `run_doctor()` in `cli/XAir_ToastSaver.c` contains:

```c
if (s->model == &MODEL_XR18) {
    /* buses 1–6: XR18 only */
    for (int n = 1; n <= 6; n++) { ... }
    /* LR: XR18 only */
    { ... }
} else {
    doc_report(..., "X32: bus GEQ/TEQ is in FX rack slot ...");
}
```

This works for two models but won't scale. Adding M32, XR16, or XR12 will
require adding more `else if` branches to a function that should not need to
know which model it is talking to.

## Target state

Add a `check_outputs` function pointer to `MixerModel`:

```c
typedef struct MixerModel_s MixerModel;

/* Signature for the model-specific bus/output check in doctor mode.
 * May be NULL (skip check entirely). Returns number of issues found. */
typedef int (*check_outputs_fn)(AppState *s, int fix,
                                DoctorItem *items, int *n_items);

struct MixerModel_s {
    const char       *name;
    int               port;
    const char       *meter_path;
    int               max_channel, max_bus, max_fx_slot;
    check_outputs_fn  check_outputs;  /* NULL = no bus-insert check */
};
```

Implement `xr18_check_outputs()` as a static function containing the existing
bus 1-6 + LR check logic:

```c
static int xr18_check_outputs(AppState *s, int fix,
                               DoctorItem *items, int *n_items) {
    int issues = 0;
    /* buses 1–6 */
    for (int n = 1; n <= 6; n++) { ... }
    /* LR */
    { ... }
    return issues;
}
```

Update `MODEL_XR18` and `MODEL_X32`:

```c
static const MixerModel MODEL_XR18 = {
    "XR18", 10024, "/meters/4",  18,  6, 4, xr18_check_outputs
};
static const MixerModel MODEL_X32 = {
    "X32",  10023, "/meters/15", 32, 16, 8, NULL
};
```

Update `run_doctor()` to dispatch via the vtable:

```c
if (s->model->check_outputs) {
    issues += s->model->check_outputs(s, fix, items, n_items);
} else {
    doc_report(s, items, n_items, -1,
               "%s: bus GEQ/TEQ is in FX rack slot — ensure bus output is routed through it",
               s->model->name);
}
```

## Acceptance criteria

- [ ] `make check` passes
- [ ] `make test-ringout-emu` passes
- [ ] `make test-ringout-emu-x32` passes
- [ ] `run_doctor()` contains no reference to `MODEL_XR18` or `MODEL_X32`
- [ ] Adding a new model (e.g. XR16) requires only: a new `check_outputs_fn`
      implementation (if needed) and a new `MixerModel` constant — zero changes
      to `run_doctor()`

## Notes

- If T-035 has landed, the signatures use `(const AppConfig*, AppRuntime*, ...)`
  instead of `AppState*`. Update `check_outputs_fn` accordingly.
- `xr18_check_outputs` should be defined immediately before `MODEL_XR18` in the
  file so the function pointer is valid at static initialisation time — but note
  that in C, static struct initialisers with function pointers are fine as long
  as the function is declared before the struct literal. A forward declaration
  works too.
- The X32 INFO message can stay inline in `run_doctor` (no vtable slot needed
  for the fallback message) — it is a general "routing is user responsibility"
  note, not model-specific behaviour.
- Do not change the FX slot check — it already works for both models and needs
  no per-model dispatch.
