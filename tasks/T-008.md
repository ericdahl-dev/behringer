## Goal

Create a test-first harness so each remaining app compilation fix starts red and ends green.

## Acceptance Criteria

- [x] A single command runs build/smoke checks for selected app targets.
- [x] Harness can express "target missing", "compile failed", "link failed", and "smoke failed" as clear failing checks.
- [x] Existing built apps `X32`, `XAir`, `X32Tap`, and `test_x32tap` are covered by passing checks.
- [x] `test_x32tap` remains part of the green suite and reports 16/16 passing.
- [x] New app build work uses one-target red-green-refactor cycles, not bulk fixes.
- [x] Hardware-dependent behavior is skipped or marked manual, not treated as CI failure.

## Notes

Public interface is command-line build behavior: run target build, inspect binary artifact, run harmless smoke/test command when possible. Do not test private C functions unless exposed through a small test binary like `test_x32tap`.

For future TUI ports, follow `X32Tap`: split logic into testable C module plus small test binary, then keep curses interaction separate.
