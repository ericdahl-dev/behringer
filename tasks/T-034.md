## Goal

Extract the reactive event loop that is currently embedded in `main()` into a
standalone `run_reactive(AppState *s)` function, mirroring the existing
`run_doctor()` / `run_ringout()` pattern. This reduces `main()` from cognitive
complexity 148 to ~30 and makes the reactive mode independently testable.

## Context

`cli/XAir_ToastSaver.c` contains three operating modes:
- `run_doctor()` — lines ~224–352
- `run_ringout()` — lines ~538–793
- reactive mode — **currently embedded in `main()`** from roughly line 1006
  through 1065

`main()` is 273 lines with cyclomatic complexity 63 and cognitive complexity
148 — almost entirely because the reactive event loop lives inside it.

## What to change

### `cli/XAir_ToastSaver.c`

1. Add a new static function `run_reactive(AppState *s)` that contains:
   - The `/xinfo` handshake (currently in main after doctor/ringout dispatch)
   - The auto pre-flight check (`if (!s->no_preflight) run_doctor(...)`)
   - The RTA source configure + subscribe_meters + /xremote send
   - The optional `ringout_load_profile` call
   - TUI init (`if (!s->verbose) tui_init()`)
   - The `while (g_running)` event loop (keepalive, select, recvfrom,
     strcmp meter path, handle_meters, key poll, resize)
   - The shutdown: `cleanup_notches` + `osc_conn_close` + print "toast saver stopped"

2. `main()` after argument parsing and validation becomes:
   ```c
   signal(SIGINT,   sig_handler);
   signal(SIGTERM,  sig_handler);
   signal(SIGWINCH, sigwinch_handler);
   toast_state_init(...);
   if (osc_conn_init(&s.conn, s.ip, s.model->port) < 0) { perror("socket"); return 1; }
   if (s.doctor) {
       /* doctor mode — unchanged */
       return 0;
   }
   if (s.ringout) {
       run_ringout(&s);
       osc_conn_close(&s.conn);
       printf("toast saver (ring-out) stopped\n");
       return 0;
   }
   run_reactive(&s);
   return 0;
   ```

   Note: the `/xinfo` handshake and preflight are currently done in `main()`
   before the ringout/reactive split. After this refactor they move inside
   `run_reactive()`. `run_ringout()` already does its own handshake implicitly
   (it reads the fader as the first step and aborts if the mixer is unreachable).
   The preflight `run_doctor` should stay inside `run_reactive` only — not run
   for `--ringout`.

3. No behaviour changes. All flags, defaults, and flow remain identical. The
   only observable difference is that `osc_conn_close` for the ring-out path
   moves out of `run_ringout` and into `main()` (it is already there — check
   this, do not double-close).

## Acceptance criteria

- [ ] `make test-ringout-emu` passes
- [ ] `make test-ringout-emu-x32` passes
- [ ] `main()` is ≤ 120 lines after the refactor
- [ ] A new static `run_reactive(AppState *s) → void` exists in
      `XAir_ToastSaver.c`
- [ ] `--doctor`, `--ringout`, and reactive mode all behave identically

## Notes

- `osc_conn_init` must happen before `run_reactive` is called (it needs the
  socket), so keep it in `main()`.
- `toast_state_init` should also stay in `main()` — it is config-time setup.
- Do NOT split `run_ringout` in this task — that is T-035 scope or later.
- Do NOT change any public API, structs, or headers.
