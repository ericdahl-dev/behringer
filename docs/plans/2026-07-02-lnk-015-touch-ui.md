# LNK-015 Touch UI Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the on-device touch UI for the Waveshare ESP32-S3-Touch-LCD-1.47 — a live status screen and a full settings screen — so X32Link can be monitored and configured from the screen alone, no phone or browser.

**Architecture:** Split the work the way LNK-014 did. All decision logic (touch hit-testing, keypad buffer, config-field mutation, value formatting, phase→angle) goes in a new **pure-C module `touch_ui.{c,h}`** with Unity host tests (TDD, runs on the dev box). All pixels + wiring go in **`touch_display.cpp`** (extends LNK-014) using raw LovyanGFX and are verified by flash-and-eyeball on the real board. The touch UI never forks config logic — it calls the existing `config_validate()` / `config_save()` in `app_config.*`, exactly like `web_config.cpp`'s `handle_save()`.

**Tech Stack:** C (pure logic + Unity tests), C++/Arduino (LovyanGFX ≥1.2.21, no LVGL), ESP32-S3, `arduino-cli`. FQBN `esp32:esp32:esp32s3:USBMode=hwcdc,CDCOnBoot=cdc,FlashSize=16M,PSRAM=opi`; build flags `-DBOARD_WAVESHARE_S3_TOUCH_LCD_147 -DHAS_TOUCH_DISPLAY` (local `build_opt.h`).

**Key existing seams (verified):**
- Touch: `axs5106l_parse()` → `axs_touch_t {count, points_len, points[].x/y}` (`axs5106l.h`). Rotation-4 map: X direct, `y = 319 - y` (LNK-014 Progress).
- Tempo: `tempo_source_bpm()` (0.0=no signal), `tempo_source_active()`, `tempo_source_beat()` (self-clearing), `tempo_source_phase(quantum)`, `tempo_source_phase_valid()`.
- Config: `AppConfig` (wifi_ssid/wifi_pass/mixer_ip/model/fx_slot/input_source/quantum_beats), `config_validate(const AppConfig*)`, `config_save(const AppConfig*)`, `config_model_slot_max(int)`.
- Display: `touch_display_begin()` / `touch_display_tick()` (LNK-014). LovyanGFX class `LGFX` + `draw_splash()` already in `touch_display.cpp`.

**Flash budget:** LNK-014 already sits at **85%**. Every task ends by re-checking flash %. If any task pushes over ~95%, stop and cut scope (defer the on-screen keyboard — see Task 12's fallback).

## Task 1: Hit-testing (`ui_hit`)

**Files:** Modify `touch_ui.{c,h}`; Test `test_touch_ui.c`

**Step 1: Failing test**
```c
void test_hit_inside_returns_index(void) {
    ui_rect_t r[] = {{0,0,10,10},{20,20,10,10}};
    TEST_ASSERT_EQUAL_INT(1, ui_hit(r, 2, 25, 25));
}
void test_hit_miss_returns_neg1(void) {
    ui_rect_t r[] = {{0,0,10,10}};
    TEST_ASSERT_EQUAL_INT(-1, ui_hit(r, 1, 50, 50));
}
void test_hit_edge_inclusive_top_left_exclusive_bottom_right(void) {
    ui_rect_t r[] = {{0,0,10,10}};
    TEST_ASSERT_EQUAL_INT(0,  ui_hit(r, 1, 0, 0));    // top-left inclusive
    TEST_ASSERT_EQUAL_INT(-1, ui_hit(r, 1, 10, 10));  // bottom-right exclusive
}
```
**Step 2:** Run `make test_touch_ui` → FAIL (undefined `ui_hit`).
**Step 3: Implement**
```c
int ui_hit(const ui_rect_t *r, int n, int x, int y) {
    for (int i = 0; i < n; i++)
        if (x >= r[i].x && x < r[i].x + r[i].w &&
            y >= r[i].y && y < r[i].y + r[i].h) return i;
    return -1;
}
```
(declare in `.h`). **Step 4:** Run → PASS. **Step 5:** Commit `feat: ui_hit hit-testing`.

## Notes for the executor
- **TDD tasks 1-6 are the spine** — they're pure C, fully host-tested, and de-risk every hardware task (drawing code just calls tested logic). Do them first, in order.
- Hardware tasks 7-12 can't be unit-tested; each ends with a specific on-device observation + a flash-% check. If flash climbs dangerously, Task 12's fallback is the release valve.
- Never duplicate `config_validate`/`config_save` — the touch UI is a second front-end, not a second source of truth (mirror `web_config.cpp`).
- Keep `touch_ui.c` allocation-free and `Arduino.h`-free so it stays host-testable.
