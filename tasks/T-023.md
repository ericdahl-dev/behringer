## Goal

Wire the pure controller (T-021) and the gain-drive plumbing (T-022) together
into a new **supervised `--ringout` mode** in `cli/XAir_ToastSaver.c`: ramp a
monitor up, notch each ring as it appears, stop at the ceiling / target margin /
max notches, and report the result.

See [`docs/ringout-design.md`](../docs/ringout-design.md).

## Acceptance Criteria

- [ ] `--ringout` selects ring-out mode (reactive remains the default). Mode is
      mutually exclusive with the live-protect loop.
- [ ] Per `/meters/4` frame: update baseline, call `ringout_step`, and execute
      the returned action — `RO_RAISE_GAIN`/`RO_BACK_OFF` → `ringout_set_gain`;
      `RO_PLACE_NOTCH` → `send_teq_band(par, db_to_geq_float(cut_db))` and record
      it in the profile; `RO_HOLD` → wait; `RO_DONE`/`RO_ABORT` → finish.
- [ ] **Supervised:** `--ringout-step` (optional) pauses for an operator keypress
      before each `RO_RAISE_GAIN` and before each notch is committed; without it,
      runs auto but still honours Ctrl-C panic (T-022).
- [ ] Live progress to the terminal: current driven gain, current margin to
      ceiling, and a marker per notch placed (reuse the existing RTA display
      where practical).
- [ ] On completion print a summary: list of notched bands (Hz + depth),
      **gain-before-feedback margin achieved**, and stop reason (ceiling / margin
      / max-notches / abort).
- [ ] Builds via `make`; `--help` documents the new flags; no regression to
      reactive mode (existing `check` tests still pass).

## Notes

- Keep `XAir_ToastSaver.c` thin — all decisions come from `ringout_step`; this
  task is glue + presentation, not new control logic.
- The in-memory result (bands + depths + margin) is the object T-024 persists;
  define it here as a small struct so T-024 only adds serialization.
